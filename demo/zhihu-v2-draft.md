# 三國志略 v2 — 当 AI 学会讲真话

> 一个开源的三国策略游戏，用物理引擎替代 AI 幻觉

---

我在做一个实验：能不能让 LLM 只讲故事，不编数据？

这是 **三國志略 v2** 的核心设计——一个把"物理引擎"和"叙事引擎"彻底分离的历史策略游戏。

## 问题：LLM 是糟糕的游戏裁判

去年我开始用 DeepSeek 做 AI 游戏的实验。最初的版本让 LLM 既当裁判又当运动员——它生成谋臣建言、模拟战斗结果、推演天下大势。

结果很快暴露了三个致命问题：

1. **幻觉注入**: 玩家可以说"191年风调雨顺"，LLM 可能当真，凭空改变粮食产量
2. **偏向玩家**: LLM 知道谁是玩家，天然倾向让玩家的决策"成功"
3. **不可复现**: 同样的输入产生不同的输出，无法测试、无法平衡

这有点像让一个能言善辩但不懂数学的人去当足球裁判——场面很好看，但比分不靠谱。

## 方案：七引擎架构

借鉴光荣《三国志》系列 30 年的设计经验，我把游戏拆成了七个独立引擎：

```
Map Engine      → 这个世界长什么样（地形、关隘、补给线）
Character Engine→ 谁住在这里（五维属性、技能、关系网）
Domestic Engine → 粮食从哪来（人口增长、税收、气候）
Military Engine → 怎么打仗（兵种相克、补给、兰彻斯特方程）
Decision Engine → NPC 想干嘛（个性档案、威胁评估、决策树）
History Engine  → 历史会怎么发展（事件触发、蝴蝶效应、RAG）
Narrative Engine→ 故事怎么讲（LLM · 只读 · 不修改状态）
```

**核心原则**：前六个引擎是纯 Python 确定性计算，零 LLM 依赖。第七引擎只在所有计算完成后生成叙事文本，绝不修改游戏状态。

## 为什么这样设计

**气候系统**用 seeded RNG——`sha256(territory:year:season:turn)`，玩家"风调雨顺"四个字匹配不到任何游戏命令，直接丢弃。

**NPC AI** 用个性权重决策树。曹操的 aggression=0.8，刘备的 mercy=0.95。每个 NPC 的决策输出是结构化的 Command[]，和玩家命令格式完全一致——物理引擎不知道谁是人类。

**历史事件**用条件触发 × gravity × (1 - deviation×0.5)。官渡之战的 gravity=0.85，但如果玩家已经大幅偏离历史（deviation=0.6），触发概率降到 0.85×0.7=0.595。历史事件可以不发生，蝴蝶效应会阻断下游事件链。
