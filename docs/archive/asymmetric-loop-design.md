# 《三國志略》非对称战争与双轨大模型对齐设计方案 (Asymmetric War & LLM-Alignment Loop)

本文件定义了由 **Lanchester 方程基础数值计算 + 大模型多轮审查对齐层 + 战争迷雾局部世界投影 + 非对称智能体决策** 构成的 5 步闭环博弈系统。

---

## 1. 核心游戏循环 (The 5-Step Loop)

游戏每一回合的计算与决策流转如下：

```
                ┌────────────────────────────────────────┐
                │ 0. 玩家与所有 NPC 玩家输入当前回合决策  │
                └───────────────────┬────────────────────┘
                                    ▼
                ┌────────────────────────────────────────┐
                │ 1. 物理引擎执行常规数值与 Lanchester 仿真│
                └───────────────────┬────────────────────┘
                                    ▼
                ┌────────────────────────────────────────┐
                │ 2. LLM 读取仿真结果进行"摩擦力对齐"与    │
                │    多轮自我审查修正，输出最终世界状态  │
                └───────────────────┬────────────────────┘
                                    ▼
                ┌────────────────────────────────────────┐
                │ 3. 局部世界投影：生成带迷雾的局部状态  │
                │    LocalWorldState[FactionID]          │
                └────────┬──────────────────────┬────────┘
                         │                      │
                         ▼                      ▼
        ┌─────────────────────────┐    ┌─────────────────────────┐
        │ 4. NPC AI 基于局部迷雾  │    │ 5. 人类玩家基于局部迷雾  │
        │    情报做长期/短期决策  │    │    与 AI 军师助手辅助   │
        │    (NPC Planner Loop)   │    │    进行下轮决策决策     │
        ┌─────────────────────────┐    ┌─────────────────────────┐
```

### 步骤 1：数值仿真层 (Lanchester Simulation)
*   **输入**：上一回合的 `WorldState`（全局真实状态） + 本回合所有势力（人类 + NPC）的动作指令。
*   **计算**：
    *   常规军事战役：通过物理引擎运行兰彻斯特平原/水战方程，计算出基础的伤亡预测。
    *   内政与补给：按当前季节、税率和人口计算出粮食与资金的消耗/产出。
*   **输出**：基础数值计算结果（Raw Simulation Data）。

### 步骤 2：大模型对齐与自我审查 (LLM Alignment & Self-Correction)
*   **目的**：解决兰彻斯特方程等连续数学公式无法模拟的“非线性偶然事件”（如雷雨阻路、粮草遭劫、指挥官疾病、战场反水等“战争摩擦力”）。
*   **机制**：
    1.  **投喂上下文**：将基础数值结果、当前气候、历史事件参考（如“赤壁前夕曹操水土不服”）、随机概率因子投喂给 LLM。
    2.  **LLM 修正输出（对齐）**：LLM 结合这些非线性因素对数值结果进行**微调**（例如：“由于突发大雨，兰彻斯特方程算出的曹军撤退伤亡额外增加 15%”）。
    3.  **多轮自我审查 (Self-Reflection Loop)**：
        为了防止大模型产生数值幻觉（例如把 200 人的局部摩擦写成 5 万人大溃败），我们在 Prompt 中设定约束范围，并由内部 Agent 模块检查其输出的 JSON 状态更改值。如果偏差超过阈值（如超过基础 Lanchester 仿真伤亡的 $\pm 25\%$），则退回重试：
        > *“审查器提示：您刚才修正的曹操军伤亡比例为 80%，超出了规定的合理阈值（最大 25%）。请重新调整事件叙事并修正数值，确保历史合理性。”*

### 步骤 3：战争迷雾与视角投影 (Fog-of-War Projection)
*   **真实世界 vs 观测世界**：系统维护全局真实状态 `WorldState`，但不对玩家和 NPC 暴露。
*   **投影接口**：
    ```python
    LocalWorldState = project_local_state(WorldState, faction_id)
    ```
    *   *完全可见*：本势力的所有城池、武将忠诚度、详细资源。
    *   *边界可见*：接壤城池的驻军估算值（带有波动区间，如 `兵力: 18000~22000`）。
    *   *全局已知*：史官发表的公开演义纪事（Chronicle Log）、盟约签署公告。
    *   *不可见（迷雾）*：远端势力的真实粮仓存量、隐藏在山谷中的伏兵。

### 步骤 4：NPC 玩家决策 loop (Asymmetric NPC AI)
*   **非对称决策**：NPC 智能体读取的是自己的 `LocalWorldState`，而非上帝视角的全局状态。
*   **决策逻辑**：
    *   曹操的 AI 可能会因为侦察兵报告“刘备新野守军仅 2000”而发起进攻，却不知道刘备在后方密林中布置了 8000 伏兵（信息差导致的诱敌深入战略）。
    *   NPC 内部通过 Heuristic 快速应对战术危机，通过大模型模拟君主做出宏观外交和战略布局。

### 步骤 5：人类玩家与 AI 军师助手 (Player & Advisor Assistant)
*   **AI 军师助手**：
    *   玩家可以通过聊天框询问自己的军师（如诸葛亮）：“我军现在进攻宛城胜算几何？”
    *   军师读取玩家当前的 `LocalWorldState`（有限情报），分析对手的公开状态并回答：“亮观宛城近日粮价高涨，虽有守兵万余，但恐其军心不稳。若我军速战，三成胜算；若能诱其出城合围，则有七成胜算。”
    *   这把冷冰冰的数字和迷雾情报，转化为了极具沉浸感和谋略感的角色对话。

## 2. 状态结构设计

### 全局真实状态 (`WorldState`)
```json
{
  "turn": 4,
  "factions": {
    "cao": { "treasury": 45000, "food": 85000, "actual_troops": 120000 },
    "shu": { "treasury": 3200, "food": 4000, "actual_troops": 5000 }
  },
  "armies": {
    "cao_vanguard": { "location": "wancheng_road", "troops": 15000, "hidden": false },
    "shu_ambush": { "location": "xinye_forest", "troops": 3000, "hidden": true }
  }
}
```

### 投影后的刘备势力状态 (`LocalWorldState["shu"]`)
```json
{
  "my_faction": { "treasury": 3200, "food": 4000, "actual_troops": 5000 },
  "armies": {
    "shu_ambush": { "location": "xinye_forest", "troops": 3000, "hidden": true }
  },
  "perceived_factions": {
    "cao": {
      "treasury": "unknown",
      "food": "unknown",
      "estimated_troops": "100000~140000"
    }
  },
  "visible_armies": {
    "cao_vanguard": { "location": "wancheng_road", "estimated_troops": "12000~17000" }
  }
}
```

## 3. 子任务拆解与后续开发路线

为了推进这个具有高度创新性的非对称对齐系统，后续开发可拆解为以下阶段：

### 阶段 5: 大模型对齐与自我审查层实现 (Phase 5)
*   **Task 5.1: 构造对齐 Prompt 与约束格式**
    *   设计 `alignment_prompt`，将 Lanchester 方程计算出的死伤人数与随机摩擦事件（如恶劣天气）输入大模型，要求输出符合约束边界的 JSON 调整值。
*   **Task 5.2: 审查器（Reflective Validator）实现**
    *   编写校验逻辑，若 LLM 输出的调整数值超过物理仿真结果的限额（如 $\pm 25\%$），自动触发 Re-prompt 进行自我修正，直至数值对齐。

### 阶段 6: 局部世界状态投影与迷雾 (Phase 6)
*   **Task 6.1: 投影逻辑实现**
    *   编写 `LocalWorldStateProjector`，依据接壤关系和侦察程度，生成混淆和模糊后的势力与军队状态。
*   **Task 6.2: 侦察与反侦察命令集 (Reconnaissance Orders)**
    *   在 Command 集中新增 `scout` (探索邻近迷雾) 和 `disinform` (散布假情报以误导对方的 perceived 兵力值) 等行动。

### 阶段 7: AI 军师助手模块与 NPC 规划器统一 (Phase 7 Unified Strategic Advisor)
*   **对称性设计原则**：人类玩家的“AI 军师（诸葛亮/荀彧）”与 NPC 的“AI 决策规划器”在逻辑上是完全对称的。它们均接受当前的 `LocalWorldState`（局部有限视野）、本势力的君主性格特质（aggression, cunning 等）、以及一个自然语言提问（人类是玩家问句，NPC 是系统生成的大局评估请求），并输出策略分析叙事与指令建议权重。因此，它们应当由同一个统一的 `StrategicAdvisor` 类来实现。
*   **Task 7.1: 统一军师/规划器分析接口**
    *   在 `histrategy/llm/advisor.py` [NEW] 中实现 `StrategicAdvisor` 类。
    *   该类支持 `evaluate_strategy(local_state, personality, query=None) -> dict` 方法。
    *   人类玩家提问时，传入玩家的 `local_state` 与问题文本，返回军师的锦囊妙计（文本）。
    *   NPC AI 决策时，传入 NPC 自身的 `local_state` 与性格，返回局势大局观分析（文本）以及各地区进攻/防守的建议权重数据（结构化数据），供 `DecisionEngine` 转换成执行指令。
