# 三國志略·宏观历史模拟引擎 — 产品设计文档 (PRD)

> 版本: 0.1 | 2026-06-12 | Prometheus
> 状态: 草案 — 待用户审阅

---

## 一、产品愿景

**"历史实验室"** — 不是玩游戏，是在做实验。

用户扮演一位割据君主（曹操/刘备/孙权等），以**策令（法令、经济政策、外交方略、人事任命）**的形式下达季度指令。AI 基于确定性经济/人口/民心模型 + LLM 推演 + 正史黑天鹅事件，生成每个季度的历史走向。

用户在过程中**学到真实的历史逻辑、权谋智慧、制度演化**——而不是练操作手速。

### 一句话

> "如果我在 207 年实行屯田制而非扩军备战，三国历史会怎样改写？——用 AI 回答这个问题。"

---

## 二、目标用户

### 核心用户 Persona: "历史思考者"

- 25-45 岁男性为主
- 读过《三国演义》和部分《三国志》
- 刷知乎历史话题、看 B 站历史 UP 主
- 玩过光荣三国志但觉得"太像填表"
- 对"如果历史是另一种走向"有天然好奇
- 愿意为深度内容付费（¥30-50/月）

### 次要用户

- **教育者**：历史老师用游戏做教学工具
- **公务员/管理者**：通过历史模拟理解制度设计
- **穿越小说读者**：想看"文字版"架空历史

## 三、核心体验设计

### 3.1 游戏循环

```
┌─────────────────────────────────────────────┐
│  季度开始 (208年春)                          │
│  ├── 情报简报 (自动生成)                     │
│  │   ├── 天下大事 (黑天鹅/历史事件)           │
│  │   ├── 势力状态 (兵力/经济/民心/领地变化)    │
│  │   └── 外交动态 (结盟/宣战/中立)            │
│  │                                           │
│  ├── 廷议 (LLM 生成的朝堂讨论)               │
│  │   ├── 谋士进言 (3-4条策略建议)             │
│  │   ├── 引用史料 (弹窗链接)                  │
│  │   └── 现代学者观点 (弹窗链接)              │
│  │                                           │
│  ├── 【玩家决策】— 自由文本策令               │
│  │   "实行屯田制，税率从40%降至30%，            │
│  │    任命荀彧为尚书令主管内政，               │
│  │    遣使与孙权结盟抗刘..."                   │
│  │                                           │
│  ├── AI 推演 (30-60秒)                       │
│  │   ├── 确定性引擎：经济/人口/民心数值更新    │
│  │   ├── LLM 模拟：战役结果/外交反应/黑天鹅   │
│  │   └── Guardrail：验证数值合法性            │
│  │                                           │
│  └── 季度结果                                │
│      ├── 史书纪事 (叙事体)                    │
│      ├── 数据看板 (势力对比图/趋势图)          │
│      └── 知识卡片 (本回合涉及的历史知识点)     │
└─────────────────────────────────────────────┘
```

### 3.2 策令系统 (用户可操作)

用户用**自由文本**下达指令，IntentParser 解析为结构化策令：

| 策令类别 | 示例 | 影响维度 |
|---------|------|---------|
| **法令** | "实行屯田制"、"推行九品中正制" | 经济产出、民心、人才流动 |
| **税率** | "将税率从40%降至25%" | 税收、民心、人口增长 |
| **人事** | "任命荀彧为尚书令，罢免程昱" | 行政效率、派系关系 |
| **外交** | "遣使与孙权结盟，共抗曹操" | 关系值、联盟、贸易 |
| **宣战** | "对刘表宣战，目标襄阳" | 战争触发（LLM 模拟结果） |
| **求和** | "向曹操称臣纳贡" | 关系值、朝贡体系 |
| **迁都** | "从许昌迁都至洛阳" | 行政中心、地理优势 |
| **情报** | "派遣细作潜入江东" | 情报准确度 |

**注意：用户不操作具体军队。**"宣战"后，战役结果由 LLM 基于兵力对比+地形+将领+历史事件综合推演。

### 3.3 知识层设计 (核心差异化)

这是"历史实验室"区别于一般游戏的关键——**知识不是 flavor text，是一等公民**。

每个游戏事件附带三类知识弹窗：

#### A. 史料引用
```
┌─────────────────────────────────┐
│ 📜 史料：《三国志·魏书·武帝纪》    │
│                                 │
│ "是岁，太祖乃兴屯田，以任峻为     │
│  典农中郎将，募百姓屯田于许下，   │
│  得谷百万斛。于是州郡例置田官，   │
│  所在积谷。"                     │
│                                 │
│ → 你正在做的，就是曹操在196年做的  │
└─────────────────────────────────┘
```

#### B. 现代学术解读
```
┌─────────────────────────────────┐
│ 🎓 学者视角：田余庆《秦汉魏晋史》  │
│                                 │
│ "曹操屯田制的核心不是经济效率，    │
│  而是将流民与土地重新绑定——本质   │
│  上是人口控制制度。这解释了为何     │
│  屯田制下的农民地位低于自耕农。"   │
│                                 │
│ → 你的"屯田"不仅是加粮食产出，    │
│   还会降低人口流动性、增加社会控制  │
└─────────────────────────────────┘
```

#### C. 系统逻辑解释
```
┌─────────────────────────────────┐
│ ⚙️ 引擎逻辑：税率下调的影响链      │
│                                 │
│ 40% → 30%:                      │
│ ├── 短期税收 -2,000金/季度       │
│ ├── 民心 +8 (3个月内)            │
│ ├── 人口增长加速 +0.5%/季度       │
│ ├── 商业投资意愿上升               │
│ └── 长期(2年): 税收反超因税基扩大  │
│                                 │
│ 历史上：汉文帝"三十税一"(~3.3%)    │
│ 造就了文景之治的税基扩张           │
└─────────────────────────────────┘
```

### 3.4 黑天鹅事件系统

正史/演义中的关键事件，在游戏中以概率触发。触发条件由游戏状态决定：

| 事件 | 触发条件 | 概率 |
|------|---------|------|
| 三顾茅庐 | 刘备势力存活 + 207年 | 90% |
| 官渡之战 | 曹操 vs 袁绍 + 200年 | 80% |
| 赤壁之战 | 曹操占荆州 + 208年 | 85% |
| 刘表病亡 | 208年 | 75% |
| 周瑜病亡 | 210年 | 60% |
| 荀彧之死 | 曹操称公/称王 | 70% |
| 司马懿政变 | 曹魏稳定 + 249年 | 40% |

事件结果由 LLM 根据当前游戏状态动态生成（而非固定脚本），形成"历史引力 + 玩家偏离"的涌现效果。

## 四、UI 概念设计

### 4.1 不是纯聊天界面

现有 histrategy 是 chat UI。宏观引擎需要的是一种**混合界面**：

```
┌──────────────────────────────────────────────────────┐
│  三國志略 · 曹操势力 · 208年春 · 第5季度              │
├────────────────────┬─────────────────────────────────┤
│                    │                                 │
│   📊 天下大势       │   📜 廷议                        │
│                    │                                 │
│   [势力对比雷达图]   │   荀彧进言："明公，去岁屯田已见   │
│   [领地地图简图]    │   成效，许昌粮仓充盈。然税率仍    │
│   [经济趋势折线]    │   居高不下，百姓颇有怨言..."      │
│                    │                                 │
│   ┌──────────┐     │   [📜 史料] [🎓 学者视角]        │
│   │ 兵力 15万 │     │                                 │
│   │ 粮草 3.5万│     │   司马懿："孙权已遣鲁肃入川联络   │
│   │ 民心 62  │     │   刘璋，若孙刘联盟成，我腹背受敌..." │
│   │ 领地 9郡 │     │                                 │
│   └──────────┘     │   ─────────────────────────────  │
│                    │   ✏️ 请输入策令:                  │
│   [📖 本回合知识]   │   "实行屯田制，税率降至30%..."     │
│   屯田制 九品中正   │                                 │
│   孙刘联盟 荆州地理  │   [提交] [查看百科] [回看历史]    │
│                    │                                 │
├────────────────────┴─────────────────────────────────┤
│  ⏮ 207年冬 | 208年春 (当前) | 208年夏 ⏭              │
└──────────────────────────────────────────────────────┘
```

### 4.2 关键 UI 元素

| 元素 | 说明 | 优先级 |
|------|------|--------|
| **势力看板** | 兵力/经济/民心/领地的可读卡片 | P0 |
| **领土简图** | 基于 HTML/SVG 的简化地图，显示势力分布 | P1 |
| **趋势图** | 折线图显示玩家势力的经济/民心/兵力历史 | P2 |
| **知识弹窗** | 点击关键词弹出史料/学术解读 | P0 |
| **时间轴** | 底部可选季度，可回看历史回合 | P1 |
| **廷议对话框** | LLM 生成的谋士进言，附知识链接 | P0 |
| **策令输入框** | 自由文本输入 + 建议模板 | P0 |
| **百科系统** | 人物/地名/制度/战役的可搜索知识库 | P1 |

### 4.3 内容深度 vs 操作门槛

关键设计原则：**默认可读，深入可查**。

- 第一层（默认显示）：简洁的叙事文本 + 关键数据卡片——类似读新闻摘要
- 第二层（点击展开）：知识弹窗、势力对比、趋势图表——为想深究的用户
- 第三层（搜索/百科）：完整的知识库、史料索引——为教育型用户

这保证了"不想动脑子的用户看 AI 讲故事就行"，同时"想学习的用户可以深挖到史料引用"。

## 五、成功指标

### 北极星指标

**"玩家历史理解深度"** — 难以量化，但可以 proxy：
- 回访率（次日/7日）：≥40%/20%
- 平均会话时长：≥30 分钟
- 知识弹窗点击率：≥15%
- 策令多样性（不同类别策令的使用率）

### 商业指标

- 免费额度：5 回合（体验完整循环）
- 订阅定价：¥30/月 或 ¥288/年
- 首月转化率目标：5-10%（从免费到付费）
- 月留存（付费用户）：≥60%

## 六、不做的事（Anti-Scope）

为了集中力量，明确以下**不做**：

1. ❌ **不做实时战斗/微操** — 战役全部由 AI 模拟
2. ❌ **不做 3D/复杂动画** — 界面是文字+简图+SVG
3. ❌ **不做多人联机** — 先做好单机体验
4. ❌ **不做角色扮演/CK3 式人物模拟** — 人物是功能单位，不是叙事主体
5. ❌ **不做手机原生 App** — 响应式 Web 即可
6. ❌ **不做 Steam 发布** — 初期 Web 端验证，3-6 个月后评估
7. ❌ **不做大量剧本** — 初始只做 207 剧本（三顾茅庐前夕），验证后再扩展

## 七、与现有 histrategy 的关系

| 维度 | 现有 histrategy (v2/v3) | 宏观引擎 |
|------|------------------------|---------|
| 分辨率 | 回合（月） | 季度 |
| 用户操作 | 调兵、攻击、移动 | 策令（法律/经济/外交/人事） |
| 战斗处理 | 确定性计算 + LLM 覆盖 | 纯 LLM 推演 + 黑天鹅注入 |
| 知识层 | 无 | 史料引用 + 学术解读 + 系统逻辑 |
| UI | 纯聊天 | 混合：聊天+看板+弹窗+地图 |
| 目标用户 | 策略游戏玩家 | 历史思考者 |

**复用**：
- ✅ 确定性引擎的势力模型（FactionState, Territory, Character）
- ✅ 知识库数据（characters.json, factions.json, territories.json）
- ✅ LLM 基础设施（adapter, prompt_loader）
- ✅ 黑天鹅事件池（history_engine 的事件定义）
- ✅ TurnMemory 系统

**重写**：
- 🔄 命令系统（从 battle commands → policy commands）
- 🔄 WorldSimulator（从战斗覆盖 → 季度推演）
- 🔄 前端 UI（从纯 chat → 混合界面）
- 🔄 IntentParser（从解析战斗指令 → 解析策令）
- 🔄 NarrativeEngine（从回合叙事 → 季度史书纪事 + 知识输出）
